## 1. Диагноз: почему это читается как поделка

Продукт не выглядит недоделанным. Он выглядит **несобранным**: каждый экран по отдельности
продуман (комментарии в коде — это, честно говоря, лучшая проектная документация, какую я
видел), но между экранами нет ни одной общей единицы измерения. Семь корней:

1. **Нет системы.** В `styles.css` 16 разных значений отступов, 15 размеров шрифта,
   10 радиусов и **две несовместимые палитры** одновременно (Tailwind slate/sky для
   поверхностей и GitHub Primer для состояний). Ничто не выровнено ни по какой сетке,
   потому что сетки нет. Это и есть главный источник ощущения «самодел»: глаз видит, что
   расстояния между блоками случайны.
2. **Композиция строится вложенными карточками, а не таблицами.** Список эндпоинтов — это
   стопка мини-карточек переменной высоты, внутри каждой ещё две панели переменной высоты.
   Такая конструкция физически не может стоять на месте и физически не может быть плотной.
3. **Уровень один переполнен.** Правило «не более трёх цифр» нарушено в самом продукте:
   `FlowPanel` показывает четыре цифры плюс бейдж заморозки, `PathPanel` — три, и обе панели
   рисуются на **каждой** молчащей строке. Для игры это шесть строк × семь цифр.
4. **Объяснения всё-таки просочились на страницу**, несмотря на правило от 02.08. Подписи
   групп (`udpHint`, `tcpHint`), подсказка пикера, предупреждение о разогреве, три пункта
   «Why this is not the ping your game shows» **на каждой строке** — это абзацы, конкурирующие
   с цифрами, которые они описывают.
5. **Справка — не страница, а свалка.** 26 тем плоским списком, каждая — один `<h3>` и один
   `<p>` на 150–250 слов, без оглавления, без группировки, без поиска, без возврата назад.
6. **Механизм объяснений сам стал шумом.** Правило «ⓘ у каждой цифры» при двадцати
   соединениях даёт до 260 одинаковых значков на экране (§5). Значок, повторённый двести
   раз, ничего не объясняет — он мешает найти цифру.
7. **График не участвует в чтении.** Единственный результат наведения на линию происходит
   не на графике, а в списке ниже, возможно за пределами вида. Ни тултипа, ни легенды, ни
   курсорной метки, ни клавиатуры (§6).

## 2. Дефекты (это ошибки, а не вкусовщина) — P0

Эти семь пунктов чинятся независимо от всей остальной перестройки и стоят дёшево.

### 2.1 На цифрах нет единиц измерения

`formatMs` и `formatPct` возвращают голое число.

```ts
// src/shared/format.ts:25
export const formatMs = (value, locale) => value === null ? NO_VALUE : fmt.format(value);
export const formatPct = (value, locale) => value === null ? NO_VALUE : fmt.format(value);
```

На экране это `Ping (RTT) 42`, `Jitter 3`, `Loss 3`. **«Loss 3» — это три процента или три
пакета?** `CLAUDE.md` требует «names that spell out units», а единицы есть только у байтов
(`kB`), у секунд (`{{seconds}} s`) и у заморозки (`Frozen for {{ms}} ms`). Всё остальное —
без единиц. Для аудитории, которая не знает, что такое джиттер, это ломает не эстетику, а
понимание.

**Правка:** единицы — через i18next, не хардкодом.

```json
"unit": {
  "ms": "{{value}} ms",
  "pct": "{{value}} %",
  "perSecond": "{{value}}/s"
}
```

Прочерк остаётся прочерком без единицы: `—`, а не `— ms`.

### 2.2 Класс `nm-health--bad` не существует

```tsx
// src/features/app-monitor/FlowPanel.tsx:66
<span className="nm-health nm-health--bad">{t('apps.passive.stall', ...)}</span>
```

В `styles.css` такого класса нет. Бейдж заморозки получает только базовый
`border: 1px solid currentcolor` и наследованный цвет — то есть выглядит как нейтральная
плашка. Это **самый сильный сигнал «прямо сейчас что-то сломано»** во всём приложении, и он
не оформлен. Нужен `--nm-unreachable`.

### 2.3 Абзацы в справке не рендерятся

Тело темы `network` содержит `\n\n` (четыре абзаца), но рендерится так:

```tsx
// src/features/help/HelpPage.tsx:70
<p className="nm-help-page__body">{t(bodyKey(entry))}</p>
```

Внутри `<p>` переводы строк схлопываются в пробел. Самая длинная тема справки выводится
одним сплошным куском на ~350 слов. Тело должно разбиваться по `\n\n` в массив `<p>`.

### 2.4 Группа TCP открывается и закрывается сама

```tsx
// src/features/app-monitor/EndpointGroup.tsx:121
<details className="nm-endpointgroup" open={group.needsAttention}>
```

`open` здесь неуправляемый, но React переприменяет его при каждом изменении значения.
`needsAttention` — это «хоть один эндпоинт не Ok», состояние, которое при слабой сети
переключается постоянно. **Секция открывается и схлопывается под читателем, сдвигая всё
ниже.** Это прямой вклад в «прыгающий интерфейс». Нужно: `needsAttention` задаёт только
*начальное* состояние; дальше решение принадлежит пользователю, а новая проблема в свёрнутой
группе объявляется бейджем в заголовке, а не самораскрытием.

### 2.5 Дубли в CSS

- `.nm-visually-hidden` объявлен дважды (строки 599 и 1131) с **разной** реализацией
  (`clip: rect(...)` против `clip-path: inset(50%)`, второй теряет `border: 0`).
- `.nm-endpoint__age` объявлен дважды (702 и 810), второй молча переопределяет первый.

### 2.6 Нет видимого фокуса почти нигде

`:focus-visible` есть только у `.nm-endpoint__select` и `.nm-timeline`. У `.nm-button`,
`.nm-nav__tab`, `input`, `select` и всех `<summary>` — ничего, то есть дефолт браузера,
почти невидимый на тёмном фоне. При том что вся кодовая база построена вокруг клавиатурной
доступности (ⓘ — кнопка именно ради этого), это противоречие. Нужно одно общее правило:

```css
:where(button, a, input, select, summary, [tabindex]):focus-visible {
  outline: 2px solid var(--nm-accent);
  outline-offset: 2px;
  border-radius: var(--nm-radius-sm);
}
```

### 2.7 Панель ⓘ обрезается у правого края

```css
.nm-help__panel { position: absolute; left: 0; width: min(22rem, 60vw); }
```

Жёсткое `left: 0` без переворота. У ⓘ в правой колонке (`FlowPanel`, бейджи, правая часть
таблицы) панель уходит за границу окна. Нужен переворот на `right: 0`, когда до правого края
меньше ширины панели.

## 3. Прыгающий список соединений

Шесть независимых причин. `holdPlace` закрывает только одну из них и только для
закреплённой строки.

| # | Причина | Что происходит |
|---|---|---|
| 1 | Rust переупорядочивает список worst-first | Любая смена состояния переставляет строки местами |
| 2 | `<details open={needsAttention}>` (см. 2.4) | Целая секция раскрывается/схлопывается сама |
| 3 | `PathPanel` / `FlowPanel` появляются позже строки | Строка вырастает на ~100 px, когда приходит первый замер маршрута |
| 4 | `WhyNotYourPing` появляется при `answersNothing` | Строка вырастает ещё на строку текста |
| 5 | Четыре разные системы брейкпоинтов на одной странице | `minmax(24rem)`, `minmax(19rem)`, `minmax(17rem)`, `minmax(14rem)` — при изменении ширины окна колонки перестраиваются в четыре разных момента |
| 6 | Имя сети приходит асинхронно | Меняется ширина строки идентичности, возможен перенос |

**Ключевой вывод: пока строка — это карточка переменной высоты, никакие заплатки не
помогут.** Строка должна стать строкой таблицы с фиксированной высотой, а всё
переменное — уйти в раскрывашку. Это пункт 4.2.

Дополнительно, независимо от таблицы:

- **Заморозка порядка на время чтения.** Сейчас `holdPlace` держит одну закреплённую строку.
  Нужно: пока указатель над списком или в списке есть фокус — порядок от Rust
  буферизуется и применяется через 2 с после ухода. Это состояние вида, не бизнес-логика
  (прецедент — сам `holdPlace`), так что живёт в TS.
- **Одна система брейкпоинтов.** Один набор: `--nm-col-narrow: 18rem`, `--nm-col-wide: 26rem`,
  и больше никаких значений в `minmax()` по всему файлу.

**Почему таблица честнее нынешних панелей, а не просто плотнее.** Сегодня правило «никогда
не объединять маршрут и поток в одну цифру» держится на том, что панели визуально
разделены. В таблице оно становится **видимым фактом**: у молчащего match-сервера колонка
`Ping` пуста, а колонка `Route` заполнена, и читатель видит это разом по всем строкам. Это
сильнее любого абзаца.

**Что куда уехало (ни одна цифра не удалена):**

| Что | Было | Стало |
|---|---|---|
| Ping / Jitter / Loss | уровень 1, строка-карточка | уровень 1, ячейки таблицы |
| Route RTT | уровень 1, панель на каждой строке | уровень 1, колонка; полностью — в раскрывашке строки и в блоке «Busiest flow» |
| Route jitter / loss | уровень 1, панель | **уровень 2** (раскрывашка строки) |
| Позиция маршрута («stops inside your provider») | уровень 1, панель | уровень 1 у самого нагруженного потока; **уровень 2** у остальных |
| Updates / Arrival jitter / Worst pause / Drop-off | уровень 1, панель на каждой строке | уровень 1 у самого нагруженного потока; **уровень 2** у остальных |
| Freeze (заморозка) | уровень 1 | **уровень 1 везде, без исключений** — это предупреждение, оно не понижается |
| Имя сети, возраст | уровень 1 | уровень 1 (колонка `Network`, возраст — в раскрывашку) |
| `WhyNotYourPing` | на каждой молчащей строке | **один раз на карточку**, под графиком |
| Подписи групп (`udpHint`/`tcpHint`) | на странице | **уровень 3** — ⓘ у заголовка группы |
| Pool «None for this application» | целая панель | одна приглушённая строка; панель — только когда пул есть |
| Warmup-абзац | абзац на уровне 1 | бейдж `Warming up · 12 s` + ⓘ (текст уже есть в теме `warmup`) |
| Пикер приложений | всегда развёрнут сверху | свёрнутая строка, разворачивается по клику |

**[нужно решение] Изменение правила в `CLAUDE.md`.**

> Цитата (раздел «Два уровня глубины», уровень один): «What the thing is, one word of state,
> and at most three figures. Nothing else.»

*Чего это стоит читателю сейчас, конкретно.* Правило уже нарушено в собранном продукте:
`FlowPanel` показывает четыре цифры плюс бейдж заморозки, а рядом `PathPanel` — ещё три, и
обе панели рисуются на каждой молчащей строке. То есть для игры на уровне один сейчас не
три цифры, а **семь на каждый эндпоинт** — просто разложенные по панелям так, что формально
«три на панель». Правило соблюдается по букве и грубо нарушено по смыслу.

*Формулировка замены (можно вставлять в `CLAUDE.md`):*

> **Level one — the default.** What the thing is, one word of state, and at most three
> figures **about one subject**. Where a row necessarily carries two subjects — the endpoint
> and the route to the router short of it — it may carry up to three figures about each,
> **only in a table whose column headings name which subject each column belongs to**. A
> layout that cannot name the subject in a heading gets three figures total.

*Что это стоит.* Ширина: семь колонок в русской локали (заголовки длиннее на 20–35 %)
требуют коротких форм — `Ping`, `Джиттер`, `Потери`, `Маршрут`. CPU/RAM/бюджет проб — ноль,
это чисто разметка. Приватность — ноль. Инженерно: переписать `EndpointRow` в строку
таблицы, перенести часть полей в раскрывашку, переписать `EndpointRow.test`.

*Рекомендация:* принять. *Если нет* — второй лучший вариант: оставить панели, но рисовать их
**только у самого нагруженного потока и у раскрытой строки**, а остальным строкам оставить
три цифры и прочерк. Это даёт примерно 70 % выигрыша по плотности без правки правила, но
теряет то самое видимое сопоставление пустой `Ping` и заполненной `Route` по всем строкам.

### 4.3 «Busiest flow» — откуда берётся и почему это не роль

Заголовок карточки должен вести с того эндпоинта, ради которого пользователь пришёл. Но
`view.rs` справедливо отказывается размечать эндпоинты по роли:

> «no endpoint is labelled by role, because everything except the transport and the traffic
> volume would be a guess»

**Объём трафика — как раз то, что там названо измеряемым.** Поэтому «самый нагруженный
поток» = эндпоинт с наибольшим `recentBytes` в текущем окне, и это факт, а не догадка.
Решение принимает Rust (`AppView.primaryEndpoint: string | null`), как и все прочие
суждения в этом продукте.

Честность обязательна: если два потока в пределах двойки друг от друга — **нет главного**,
блок не рисуется, показывается только таблица. Строка на этот случай:

```json
"apps.primary.heading": "Busiest flow",
"apps.primary.none": "No single endpoint is carrying most of this application's traffic."
```

### 4.4 «Match traffic» / «Supporting connections» — переименование

Твоя претензия точна, и в коде уже лежит её обоснование. `view.rs:1147` отказывается
навешивать роль по транспорту, а локаль делает ровно это:

```json
"apps.group.udp": "Match traffic",
"apps.group.udpHint": "The connections a game actually plays over",
"apps.group.tcp": "Supporting connections",
"apps.group.tcpHint": "Sign-in, launchers and content networks — not where the game is played"
```

Для Discord «Match traffic» — это голос. Для браузера — QUIC. Для торрент-клиента — пиры.
И наоборот: часть игр играет по TCP, и тогда «supporting» — прямая ложь на самой важной
строке.

**Рекомендую вариант А.** Правило от 02.08 («уровень один несёт стандартный сетевой термин,

## 5. Иконки ⓘ — их слишком много, и это следствие правила

*Добавлено после замечания пользователя, 03.08.2026.*

### 5.1 Сколько их на самом деле

Я посчитал по разметке.

**Одна строка эндпоинта, который молчит** (нормальное состояние match-сервера, то есть
самая важная строка на экране):

| Где | Темы |
|---|---|
| Идентичность | `network`, `age` |
| Бейджи | `tunnel` (условно) |
| `PathPanel` | `route`, `jitter`, `loss`, `network` (сеть хопа) |
| `FlowPanel` | `passive`, `freeze` (условно), `updates`, `arrivalJitter`, `worstPause`, `dropOff` |

**11–13 иконок на строку.** У измеримого эндпоинта — 6 (`network`, `age`, `tunnel`, `rtt`,
`jitter`, `loss`). Плюс на карточку: `warmup`, `chart`, `pool`. Плюс `watching` в пикере.

**Двадцать соединений — это от 130 до 260 иконок ⓘ на одном экране**, и все они
повторяют примерно восемь разных тем. Страница `Network` не лучше: при двадцати трёх
сервисах с двумя эндпоинтами каждый — `checks` + 23 × `medianRtt` + 23 × 2 ×
(`tunnel`, `latestCheck`, `meanRtt`, `loss`) ≈ **200 иконок**.

Это не перебор в оформлении. Это ровно то, что предписано правилом:

> `CLAUDE.md`, уровень три: «**Level three — an ⓘ on every figure**»

Правило написано в единственном числе — «у каждой цифры» — и молча предполагает, что цифра
на экране одна. При двадцати повторениях одной и той же цифры оно даёт двадцать одинаковых
объяснений одного и того же.

### 5.2 Две правки, и вторая почти бесплатна

**Правка первая: убрать глиф, сделать подпись самой ссылкой на объяснение.**

Сейчас рядом со словом, которое **и так называет величину**, ставится вторая мишень,
которая ничего не называет. Подпись `Ping (RTT)` — это и есть то, что нужно объяснить;
объяснение должно висеть на ней.

```
Было:                          Стало:
  Ping (RTT) ⓘ                   Ping (RTT)
  42 ms                          ‾‾‾‾‾‾‾‾‾‾   ← точечное подчёркивание
                                 42 ms
```

Точечное подчёркивание — общепринятый знак «здесь есть пояснение», оно не читается как
ссылка наружу (что важно: наружных ссылок в этом продукте нет и не будет), не добавляет ни
одного пикселя ширины и не создаёт второй мишени для клавиатуры. Всё остальное поведение
сохраняется без изменений: открытие по наведению **и** по фокусу, «Learn more» внутри,
`Escape` закрывает. То есть `MetricHelp` не выбрасывается — он перестаёт рисовать глиф и
начинает оборачивать подпись.

```css
.nm-explains {
  border: 0;
  padding: 0;
  background: none;
  font: inherit;
  color: inherit;
  text-decoration: underline dotted;
  text-underline-offset: 0.2em;
  text-decoration-color: var(--nm-muted);
  cursor: help;
}
```

**Правка вторая: объяснять один раз на поверхность, а не один раз на строку.**

В таблице из §4.2 подпись величины существует ровно один раз — в заголовке колонки. Значит
объяснение автоматически схлопывается с двадцати до одного. То же на странице сервисов:
`Ping, last check` / `Ping, mean` / `Loss` объясняются один раз в шапке таблицы, а не
на каждой из сорока шести строк.

**Итог по числам:**

| Экран | Сейчас | После |
|---|---|---|
| Applications, 20 эндпоинтов | 130–260 | **9** (7 заголовков колонок + `chart` + `pool`) |
| Network, 23 сервиса | ≈ 200 | **6** (`checks`, `medianRtt`, `latestCheck`, `meanRtt`, `loss`, `tunnel`) |

Ни одна тема справки не удалена, ни одна цифра не осталась без объяснения. Изменилось
только то, что объяснение живёт при **имени** величины, а имя есть один раз.

**Что с бейджами.** `tunnel` — не цифра, а причина, по которой цифры рядом измерены иначе,
и он повторяется на каждой строке. Его объяснение вешается на слово бейджа
(`Through a tunnel`) той же механикой; при двадцати эндпоинтах через VPN это двадцать
подчёркнутых слов, но не двадцать лишних глифов. Приемлемо.

**Чего я делать не буду и почему.** Переключатель «показывать пояснения» — очевидное
решение и неверное:

> `CLAUDE.md`: «there is no setting. A mode is a second product to keep consistent and one
> a user forgets they are in.»

Режим здесь хуже болезни: новичок, ради которого всё это писалось, выключит его в первый
день и никогда не включит обратно.

### 5.3 **[нужно решение]** Изменение правила уровня три

> Цитата: «**Level three — an ⓘ on every figure**, with one or two plain sentences shown on
> hover *and* on focus, and a "Learn more" into the bundled help.»

*Чего это стоит читателю, конкретно.* На странице Applications с двадцатью соединениями это
до 260 одинаковых значков, которые сами становятся визуальным шумом того самого рода, от
которого правило двух уровней защищает. Значок, повторённый двести раз, не объясняет —
он мешает найти цифру.

*Формулировка замены:*

> **Level three — the figure's own label is what explains it.** No separate mark stands
> beside it: the label carries the disclosure, marked as explainable and reachable on hover
> *and* on focus, with a "Learn more" into the bundled help. **A label explains itself once
> per surface, never once per row** — in a table the column heading carries it and the cells
> carry nothing; on a card the panel heading carries it and its figures carry nothing. A new
> metric is not done until it has a help topic, and the mark and the help page read from one
> list.

*Что это стоит.* Обнаружимость: подчёркнутое слово чуть менее заметно, чем значок. Гасится
одной фразой в пустом состоянии и во вступлении справки — по одному разу, а не по двести:

```json
"help.affordance": "Any label with a dotted underline explains itself — hover it, or move to it with the keyboard."
```

CPU/RAM/бюджет проб — ноль. Приватность — ноль. Инженерно: `MetricHelp` перестаёт быть
соседом подписи и становится её обёрткой; тесты, проверяющие наличие ⓘ у цифры, переписываются
на «подпись объясняет себя».

*Рекомендация:* принять. *Если нет* — второй лучший вариант: оставить глиф, но применить
только вторую правку (один раз на поверхность). Это снимает 95 % количества и не трогает
правило по букве, но оставляет лишнюю мишень рядом с каждым заголовком колонки.

## 6. График — сейчас он не поверхность чтения, а картинка

*Добавлено после замечания пользователя, 03.08.2026.*

### 6.1 Что с ним не так

Твоя формулировка точна: навёл на линию — подсветилось соединение, которое может быть вне
экрана. То есть **единственный результат взаимодействия с графиком происходит не на
графике**. Разбор:

| # | Что | Следствие |
|---|---|---|
| 1 | `legend: { show: false }` | У линий нет вообще никакой подписи на графике. Идентичность линии существует только как цветная метка в строке ниже |
| 2 | `cursor: { points: { show: false } }` | Курсор ничего не помечает — непонятно даже, какая точка «взята» |
| 3 | Тултипа нет ни в каком виде | Нельзя прочитать ни значение, ни момент времени, ни имя эндпоинта |
| 4 | `setSeries` только зовёт `onHover` | Весь эффект наведения — подсветка строки, возможно за пределами вида. **Это ровно твоя претензия** |
| 5 | `role="img"` + статический `aria-label` | Для клавиатуры график полностью мёртв: ни фокуса, ни стрелок, ни зачитываемого значения |
| 6 | На оси Y нет единицы | Голые числа, тот же дефект, что и в §2.1 |
| 7 | Клик закрепляет строку, но ничего об этом не сообщает | Пользователь не понимает, произошло ли что-нибудь |
| 8 | `HOVER_PROXIMITY = 24` px при 32 линиях на лог-шкале | Линии слипаются, выбор неоднозначен, и ничто не показывает, какая выбрана |
| 9 | Подпись `apps.chart.caption` = «Ping over time» | На графике есть пунктирные линии маршрутов, которые **не пинги**. Подпись противоречит главному правилу продукта |

Пункт 5 особенно обиден: `CheckTimeline` на странице сервисов сделан **правильно** — один
таб-стоп, стрелки внутри, текстовый readout под полосой, слово в каждой ячейке. График —
куда более важная поверхность чтения — не получил ничего из этого.

### 6.2 Что предлагаю

**Тултип становится легендой, читалкой и способом попасть в строку — одновременно.**

```
   ms                                      ┌────────────────────────────────┐
  200 ┤                        ╭─╮         │ 1:34                           │
      │                    ╭───╯ ╰──       │ ● 203.0.113.9   route   91 ms  │  ← worst first
  100 ┤        ╭───────────╯               │ ● 203.0.113.7   route   38 ms  │
      │   ╭────╯              ┊            │ ● 198.51.100.4  ping    22 ms  │  ← под курсором
   40 ┤───╯                   ┊            │ ○ 198.51.100.9  no reply       │
      │                       ┊            ├────────────────────────────────┤
   10 ┤───────────────────────┊─────       │ Select to keep it and jump to  │
      └────┬──────┬──────┬────┬──────      │ its row                        │
         0:30   1:00   1:34  2:00          └────────────────────────────────┘
```

Решения, каждое со своей причиной:

1. **Тултип перечисляет все линии в этот момент, а не только ближайшую.** Заявленная работа
   графика — «который из них выбивается»; на конкретной секунде это вопрос про все линии
   сразу. Ближайшая к курсору выделяется внутри тултипа.
2. **Каждая запись говорит, какая это величина** — `ping` или `route`. Это правило «никогда
   не сливать» применительно к тултипу: строка маршрута не должна читаться как пинг.
   Тест на отсутствие слова `ping` у маршрутных подписей расширяется на тултип.
3. **Пропуск читается словами.** `null` в слоте → `no reply`, не `0` и не молчаливое
   исключение из списка. Отсутствие остаётся отсутствием и здесь.
4. **Тултип не несёт слов о здоровье.** Только величины и момент. Список остаётся
   единственной инстанцией по состоянию — тултип не должен становиться вторым мнением.
5. **Клик по записи тултипа = закрепить + прокрутить строку в вид** (`block: 'nearest'`).
   Это прямое лечение твоей претензии: действие происходит там, где ты смотришь, и приводит
   тебя к строке, а не подсвечивает её вслепую. Прокрутка **только по клику** — прокрутка по
   наведению укачивает.
6. **Перекрестие с вертикальной линией** на текущем моменте — иначе непонятно, к какой
   секунде относятся числа в тултипе.
7. **Тултип переворачивается у краёв**, как и панель ⓘ (§2.7).
8. **Клавиатура — по образцу `CheckTimeline`**, который уже сделан правильно: график —
   один таб-стоп; `←`/`→` двигают момент, `↑`/`↓` переключают линию, `Enter` закрепляет,
   `Escape` отпускает. Под графиком — `aria-live="polite"` readout, дублирующий тултип
   текстом.
9. **Единица на оси Y — один раз, как подпись оси**, а не на каждом делении.
10. **Подпись графика перестаёт врать:** `«Ping over time · …»` → без слова «ping», потому
    что на графике есть маршруты.

Строки:

```json
"apps.chart.caption": "One point per {{seconds}} s · log scale",
"apps.chart.axisMs": "ms",
"apps.chart.axisElapsed": "Time watched",
"apps.chart.at": "At {{time}}",
"apps.chart.entryPing": "{{endpoint}} · ping {{value}}",
"apps.chart.entryRoute": "{{endpoint}} · route {{value}}",
"apps.chart.entryNone": "{{endpoint}} · no reply",
"apps.chart.pinHint": "Select to keep it and jump to its row",
"apps.chart.pinned": "Kept selected · Escape releases it",
"apps.chart.keyboard": "Left and right arrows move through time, up and down move between endpoints, Enter keeps one selected."
```

Тема справки `chart` уже существует и уже описывает лог-шкалу, ширину слота, максимум в
слоте и разрывы — трогать её не нужно, только довесить фразу про пунктир и про то, что
тултип показывает величину каждой линии по имени.

**Чего я специально не предлагаю.** Штатную легенду uPlot — это таблица, которая удвоит
высоту блока и продублирует список ниже. Зум и панораму — вопрос читателя за пять секунд
между раундами звучит «что сейчас не так», а не «покажи мне 1:34 поближе»; масштабирование
добавит состояние, которое надо сбрасывать, и разъедется с окном, которое описывает
подпись. Если понадобится — это отдельное решение, а не побочный эффект этой работы.

### 6.3 Ограничение, которое здесь не нарушается

`CLAUDE.md` требует, чтобы перерисовка шла только при видимом окне и чтобы UI не управлял
частотой выборки. Тултип и перекрестие рисуются **только по событию указателя или клавиши**,
то есть в трее их стоимость ровно ноль — там нет ни указателя, ни фокуса. Никакого
изменения бюджета.

## 7. Справка

### 7.1 Что не так

- 26 тем одним плоским списком, без группировки.
- Каждая тема — сразу полное тело на 150–350 слов. Страница целиком — примерно **6000 слов

- Нет оглавления, нет поиска, нет якорей, видимых читателю.

- `\n\n` в телах не рендерится (см. 2.3).

  вывод, ничего о себе не объясняет и не имеет ⓘ. По духу правила «метрика не готова без
  темы справки» это долг.

### 8.2 Вертикальный ритм: `gap` вместо margin

Главная причина «кривых отступов». `.nm-appcard` — обычный блок, и его дети складываются
собственными верхними полями: `1.1rem`, `1rem`, `0.85rem`, `0.75rem`, `0.35rem`. Расстояния
между блоками получаются случайными, а схлопывание полей делает их непредсказуемыми.

```css
/* было: каждый ребёнок сам решает, сколько сверху */
.nm-endpointgroup     { margin: 1.1rem 0 0; }
.nm-appcard__endpoints{ margin: 1rem 0 0; }
.nm-appcard__distribution { margin: 0.85rem 0 0; }

/* стало: контейнер решает один раз */
.nm-appcard { display: flex; flex-direction: column; gap: var(--nm-space-4); }
.nm-endpointgroup, .nm-appcard__endpoints, .nm-appcard__distribution { margin: 0; }
```

То же для `.nm-group`, `.nm-service`, `.nm-picker`, `.nm-help-page__section`. **Правило:
внутри карточек не должно остаться ни одного `margin-top`.**

Пятнадцать размеров (`0.62 0.7 0.72 0.75 0.78 0.8 0.85 0.9 0.95 1 1.05 1.1 1.15 1.2 1.4`).

```css
--nm-text-md:  0.9375rem;/* 15px — база */
```

постоянного — 12 px, и `--nm-muted` на нём не годится: нужен либо более контрастный


## 9. Экран «Network»

### 9.1 Две половины — это одно измерение, нарисованное дважды

*Указано пользователем 03.08.2026. Отменяет решение Phase 6.6, пункт 5, которое сознательно
оставило две половины «композицией, а не сплавом».*

Претензия верна, и дублирование крупнее, чем кажется на первый взгляд. Я сверил
`assets/targets/foreign.json` с `assets/targets/services.json`:

> **Два из четырёх целевых адресов зарубежной базовой линии — `discord.com` и
> `api.steampowered.com` — это ровно те же адреса, что и эндпоинты сервисов Discord и
> Steam.** Половина одной базовой линии — это второй замер строки, которая уже есть на этой
> же странице, в другом визуальном языке и под другим именем. И это ещё вдвое потраченный
> бюджет проб на один факт.

Остальное дублирование:

| Что | Половина «базовые линии» | Половина «сервисы» |
|---|---|---|
| Карточка | `GroupCard` | `ServiceCard` |
| Строка | `TargetRow` | `ServiceCard.EndpointRow` |
| История | `Sparkline` | `CheckTimeline` |
| Распределение | чипы `.nm-health` | чипы `.nm-health` (тот же CSS, другой компонент) |
| Круговой обход | заголовок группы + окно | легенда + каденция + оговорка |
| Форма в IPC | `GroupView` / `TargetView` | `ServiceView` / `ServiceEndpointView` |

**Пять имён для одного круга** на одной странице: `Ping (RTT)`, `Ping, median` (группа
базовой линии), `Ping, median` (карточка сервиса), `Ping, last check`, `Ping, mean`.

**Что уходит.** `Sparkline` рисует RTT по времени и **красит линию в цвет состояния** —
единственное место в продукте, где нарушено правило «цвет опознаёт, но не оценивает».
`CheckTimeline` рисует одну ячейку на проверку и называет шесть различимых исходов словами.
Для страницы, чей вопрос — «который из них красный», полоса строго лучший инструмент, и
остаётся она. **Это единственное, что со страницы исчезает, а не переезжает уровнем ниже**,
и исчезает потому, что заменяющий элемент несёт больше, а не меньше. Непрерывное чтение RTT
по времени живёт на графике приложений, где ему и место.

**Главное содержание слияния: базовая линия — это метка, а не список.** «Домашняя базовая
линия» и «зарубежная» — это *роли, которые играет цель*, а не отдельные инвентари; именно
поэтому две из них оказались скопированными эндпоинтами сервисов. Цели сводятся к одной
схеме с метками, дубликаты из `foreign.json` перестают быть отдельными записями, а метка
переезжает на записи сервисов.

**И тут есть ловушка, в которую нельзя падать.** Если просто удалить дубликаты, зарубежная
базовая линия схлопнется до двух anycast-резолверов DNS (`1.1.1.1`, `8.8.8.8`), которые
доступны почти отовсюду, — тощая и смещённая выборка для единственного вердикта, решающего,
советовать ли VPN. Поэтому Discord и Steam остаются в доказательной базе **как помеченные
сервисы, измеряемые один раз**, а зарубежную метку надо раздать достаточному числу
участников, чтобы выборка не была двумя DNS в одном пальто.

**Что НЕ сливается.** Измерительный слой. Окно `nm_core::health` и правило реакции
`nm_core::status` отвечают на разные вопросы; компонент, считающий одну цифру поверх обоих,
был бы ровно тем сглаживанием, которое запретила 6.6. Сливается **представление** и **схема
целей**. Разница в каденции перестаёт быть двумя подсистемами и становится **полем «интервал»
у цели** — планировщик `nm-core` с Phase 1 сортирует именно по длине интервала. Причина, по
которой сервисы медленные, — бюджет проб, а это число, а не архитектура.

**Страница после слияния:**

```
┌──────────────────────────────────────────────────────────────────────────┐
```

### 9.2 Остальное на этой странице

- **Строки слишком тяжёлые.** У каждого сервиса: заголовок, состояние, строка медианы,
  распределение, затем по каждому эндпоинту — адрес, до пяти бейджей, полоса проверок и три
  цифры. При двух десятках сервисов это очень длинный экран, на котором вопрос «что из этого
  красное» решается прокруткой.
  **Предложение:** строка по умолчанию — одна строка: `имя · состояние · полоса ·
  Ping (RTT)`. Эндпоинты, бейджи и остальные цифры — **уровень два**, раскрывашка строки.
  Раскрыты по умолчанию только те, у кого состояние хуже `Ok`. После §9.1 это относится ко
  всему списку, а не только к сервисам.
- **Чипы распределения выглядят как бейджи состояния** — один и тот же класс `.nm-health`.
  Читатель не отличает «этот сервис деградировал» от «два его эндпоинта деградировали».
  Нужна отдельная форма для счётного чипа (цифра крупнее, слово мельче, без рамки).
- **Сетки метрик не совпадают между страницами.** `.nm-service__metrics` — жёсткие
  `repeat(3, 1fr)`, `.nm-endpoint__metrics` — `flex-wrap` с `gap`. Одни и те же три
  величины на двух страницах не выравниваются друг с другом. Свести к одному компоненту
  `MetricRow`.
- **Заголовки половин исчезают вместе с половинами.** `network.baselines` = «Your connection
  and the way out» и `network.services` = «Services» были заголовками двух композиций;
  после §9.1 их место занимают четыре заголовка секций одного списка:

  Хорошая фраза «Your connection and the way out» не пропадает — она становится подзаголовком
  страницы, ровно как «What the numbers mean» стал подзаголовком справки в Phase 6.6.

## 10. Шапка и навигация

```
Сейчас:
┌──────────────────────────────────────────────────────────────────────────┐
│ Network Monitor                                                          │
│ Local, private network diagnostics                                       │
│              [Network][Applications][Help][Settings]  [Minimize] [Quit]  │
└──────────────────────────────────────────────────────────────────────────┘
```

- `.nm-app__header` — это `flex-wrap` с тремя зонами и `margin-left: auto` на действиях. При
  сужении окна вкладки и кнопки переносятся непредсказуемо. Нужна `grid` из трёх колонок
  `auto 1fr auto` с фиксированным поведением.
- Активная вкладка отличается **только цветом текста и рамки** — самый слабый из возможных
  способов. Нужна заливка или подчёркивание в 2 px.
- **Кнопка `Quit` рядом с `Minimize`.** Это ловушка: две соседние кнопки, одна сворачивает,
  вторая закрывает мониторинг совсем, разница — в приглушённости текста. Предлагаю: `Quit`
  уезжает вниз страницы `Settings` (гарантия «пользователь никогда не заперт» сохраняется —
  Settings всегда доступны), в шапке остаётся только `Minimize to tray`.
- `app.tagline` («Local, private network diagnostics») занимает строку на всех экранах и не
  сообщает ничего, что читатель не узнает за первые десять секунд. По правилу «страница
  несёт цифры и находки, а не объяснения» — убрать из шапки; место ему на первом запуске
  или в Settings.
- Вкладки — обычные кнопки с `aria-current="page"`. Это допустимо, но `role="tablist"` +
  `role="tab"` с перемещением стрелками ближе к тому, что это на самом деле.

## 11. Приёмочные проверки закрытого вида

Каждый пункт — тест, который пишется вместе с изменением. Формулировка «что показывает» и,
обязательно, «чего показывать не должен».

**Строка таблицы эндпоинтов (закрытая).**
Показывает: метку-цвет, адрес, имя сети (если известно), одно слово состояния, ячейки
`Ping / Jitter / Loss / Route` — каждая либо число с единицей, либо `—`.
**Не показывает:** вид пробы, интерфейс выхода, число хопов, вид возраста, объём трафика,
`Filtering confirmed`, окно усреднения, позицию маршрута.

**Молчащий эндпоинт.** Ячейки `Ping`, `Jitter`, `Loss` содержат ровно `—`; ячейка `Route`
содержит число; слово `ping` (в любом регистре) **не встречается** ни в одном заголовке или
значении колонки маршрута. *(Существующий тест на `PathPanel` расширяется на таблицу.)*

**Карточка приложения.** Содержит **ровно один** элемент `WhyNotYourPing` независимо от
числа молчащих эндпоинтов — сейчас их столько же, сколько строк.

**Пул отсутствует.** Рендерится одна приглушённая строка; секции с рамкой и заголовком
`The game's own reference servers` в документе **нет**.

**Пикер, что-то выбрано.** Показывает имена наблюдаемых приложений и счётчик; поля поиска,
чекбокса «Show everything running» и списка процессов в документе **нет**.

**Справка по умолчанию.** В документе 28 заголовков тем и 28 однострочных `short`; элементов
с телом темы — **ноль**. После клика «Read more» на одной теме тел ровно одно.

**Заморозка.** Бейдж `Frozen for … ms` присутствует на уровне один при любом состоянии
раскрывашек и любом уровне детализации остальных цифр.

**Единицы.** Ни одна ячейка `Ping / Jitter / Route` не содержит число без `ms`; ни одна
ячейка `Loss` — без `%`; `—` не сопровождается единицей.

**Объяснения (§5).** На карточке приложения с двадцатью эндпоинтами число элементов,
открывающих объяснение, **не зависит от числа эндпоинтов**: тест рендерит карточку с 3 и с
20 эндпоинтами и требует одинакового количества. Ни одна **ячейка** таблицы объяснений не
несёт — только заголовки колонок.

**График, тултип (§6).** При курсоре на моменте `t` тултип содержит по одной записи на
каждую нарисованную линию; запись линии маршрута содержит слово `route` и **не содержит**
слова `ping` ни в каком регистре; линия без значения в этом слоте даёт `no reply`, а не
`0` и не отсутствие записи.

**График, клавиатура (§6).** Контейнер графика — ровно один таб-стоп; `←`/`→` меняют момент,
`↑`/`↓` — линию, `Enter` закрепляет, `Escape` отпускает; под графиком существует
`aria-live="polite"` область, текст которой совпадает с содержимым тултипа.

**График, выбор (§6).** Клик по записи тултипа закрепляет эндпоинт **и** вызывает
`scrollIntoView` на его строке. Наведение — не вызывает.

**Network, ни одного двойного замера (§9.1).** Тест обходит все встроенные списки целей
(`domestic/*.json`, `foreign.json`, `services.json`) и падает, если один адрес встречается
в двух записях. Сейчас он падал бы на `discord.com` и `api.steampowered.com`.

**Network, один язык (§9.1).** На отрендеренной странице ровно один компонент строки и ровно
один компонент истории; имён для круга ровно два — `Ping, median` в заголовке секции и
`Ping (RTT)` в строке; `Ping, last check` и `Ping, mean` в закрытом виде **отсутствуют**.

**Network, доказательная база (§9.1).** Секции `Domestic` и `Foreign` несут пометку
«read by the verdict»; секции `Gaming platforms` и `Infrastructure` — не несут.

## 14. Чего я не проверял

- **Живую сборку.** Всё выше выведено из разметки, CSS и локали. Реальную плотность,
  реальные переносы строк и реальное поведение при изменении ширины окна нужно
  посмотреть — особенно §3 (прыжки) и §6.3 (размеры шрифта): часть выводов там может
  оказаться мягче или жёстче, чем на бумаге.
- **Русскую локаль.** Её ещё нет, но таблица из §4.2 — самое узкое место: семь колонок с
  заголовками на 20–35 % длиннее. Короткие формы заголовков надо проверять с настоящими
  строками, а не оценкой.
- **Поведение в трее и при сворачивании.** `useTrayLabels` я прочитал, но правило «рендер
  останавливается полностью» проверяется только на живой сборке.
- **График при одной линии и при двенадцати.** §6 разобран по исходнику `EndpointChart` и
  описывает то, чего в нём нет вовсе (тултип, клавиатура, единицы). Чего я по исходнику
  сказать не могу — насколько практически различимы двенадцать линий на лог-шкале в
  тёмной теме и хватает ли `HOVER_PROXIMITY = 24` px, когда они слипаются. Это проверяется
  только глазами на живой сборке.
